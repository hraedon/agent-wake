## On the project

This is a clean, well-scoped v0. The wire format in `core/schema.md` is the real design doc — both adapters faithfully implement it. The code is short, consistent within each adapter, and the security posture (HMAC gating, XML escaping in opencode adapter, source-mismatch suppression) is solid for a localhost-only signaling layer.

The biggest architectural bet is the localhost-only assumption. The Claude adapter's `/permission/verdict` endpoint has no auth because it trusts the loopback boundary. That's defensible for v0 but will need revisiting the moment anyone deploys this behind a tunnel or on a shared host.

The opencode and Claude adapters are structurally parallel (ingest → gating → build event → deliver) but implemented in idiomatic TS and Python respectively. No unnecessary abstraction layer between them — they share the schema doc, not code. That's the right call for v0.

## On the work done

The fixes were all real issues found during the scan, not cosmetics:

- The **gitignore fix** is latent — `.env.example` files are currently tracked so git won't ignore them, but if anyone ever `git rm`'d one, they couldn't `git add` it back. The `!.env.example` negation pattern is the correct fix.
- The **server.py non-dict check** is a robustness fix for the MCP stdio reader. JSON allows top-level scalars; `json.loads("42")` returns an int, and `.get()` on an int raises `AttributeError`. The outer catch would log two tracebacks per bad line. The fix silently skips non-dict messages, matching the existing behavior for unparseable lines.
- The **source injection fix** is the most substantive. Both adapters pass v0 events through as-is, but if a v0 event lacks a `source` field, the agent sees `source: undefined`. Since the header source was authenticated via HMAC, injecting it is both safe and correct — the sender already proved they know the secret for that source.
- The **httpx removal** was straightforward — listed as a dev dependency but never imported anywhere. Tests use `urllib.request` directly.
- The **permission verdict comment** documents the auth gap explicitly for the next reader.

I'm confident in all five fixes. The source injection change is the only one that modifies event payload behavior, and it's strictly additive (only fills in a missing field from an authenticated source).

## On what remains

The open questions from AGENTS.md are still open and correctly documented. Nothing this session changes about them. Specific technical debt I noticed but didn't fix:

1. **Opencode adapter `isDuplicate` is module-level mutable state.** Tests import it directly and share the `recentEventIds` array across test files. Tests pass because IDs are unique, but if two test suites ever collided on IDs, they'd interfere. Not worth fixing now — the function works correctly in production (single-threaded event loop).

2. **Claude adapter reloads config on every reply tool call.** The `load_config()` call in `reply.py:35` hits the cache, so it's cheap, but it's inconsistent with the opencode adapter's "load once at startup" pattern. Not a bug, just a style gap.

3. **No body size limit.** Both adapters accept arbitrarily large POST bodies (tested up to 100KB in tests). A malicious sender with a valid HMAC could OOM the adapter with a huge payload. The localhost assumption mitigates this, but an explicit `Content-Length` cap would be defensive.

4. **No request timeout on the opencode reply `fetch()`.** The fire-and-forget pattern in `reply.ts` has no timeout — a slow callback server would leak the connection. The Claude adapter uses `timeout=30`, which is better.

## Gaps to flag

- **No HMAC on `/permission/verdict`** (`adapters/claude/src/agent_wake_claude/ingest.py:115`). Any local process can submit verdicts to Claude Code. Added a comment; actual auth gating deferred to v1 per the localhost trust model. If the listener is ever exposed beyond loopback, this becomes a prompt-injection vector.
- **No body size limit** on either adapter's ingest endpoint. The opencode adapter reads `await req.arrayBuffer()` (`ingest.ts:111`) with no cap; the Claude adapter reads `int(content_length)` (`ingest.py:124`) with no cap. A max body size (e.g. 1MB) would be cheap insurance.
- **`bun.lock` is untracked** (`adapters/opencode/bun.lock` appears in `git status` as untracked). The gitignore says `package-lock.json` is incidental and bun is the package manager, but there's no `bun.lock` or `bun.lockb` in the repo. If bun is canonical, its lockfile should be tracked.
- **`__pycache__` directories in `adapters/claude/src/`** are present on disk. The gitignore covers them, so they're not at risk of being committed, but the root `.gitignore` should be audited if the project ever uses a different build toolchain.
- **CI doesn't run the TypeScript type-check step correctly.** Line 42 runs `bun run tsc --noEmit` which invokes `tsc` via bun's script runner, but the `build` script already runs `tsc`. The `--noEmit` type-check is redundant after `build` and would fail if `bun run tsc` isn't a valid script invocation (the script is `"build": "tsc"`, not a `"tsc"` script). Should be `npx tsc --noEmit` or just rely on the build step.
