## On the project

agent-wake remains a clean, narrow-scope project with unusually thorough design docs for its current code maturity. The v0 implementation plan (`design/v0-implementation-plan.md`) is prescriptive enough that most implementation decisions feel pre-made, which reduces ambiguity but also means the code is more "execute the spec" than "discover the design." The split between Python (Claude) and TypeScript (opencode) adapters is the right call — no shared runtime library makes sense between these ecosystems, and the wire format in `core/schema.md` is the shared contract.

The opencode adapter is materially simpler than the Claude one because it runs in-process and calls `client.session.prompt()` directly rather than hand-rolling JSON-RPC over stdio. The Claude adapter's `_notify.py` / raw stdio approach works but is technically the thing the v0 plan said *not* to do ("do not hand-roll JSON-RPC — the wake-probe approach was for diagnostics"). The `modelcontextprotocol` dep was already removed, but the adapter still doesn't use the SDK's notification primitives. This is a known gap from the previous session's reflection and remains unresolved — the SDK doesn't expose channel notifications yet.

## On the work done

What went well:
- The opencode test suite came together cleanly. Bun's test runner and `Bun.serve` for integration tests works well — zero-friction HTTP server setup for testing the ingest endpoint end-to-end.
- The `@opencode-ai/plugin` SDK's `tool()` helper with Zod schemas is ergonomic. Registering the reply tool was straightforward once I found the SDK types in `node_modules`.
- The TTL eviction for permission relay is simple and the tests are good — lazy eviction on every access, 5-minute window, no background threads.
- Removing `modelcontextprotocol` from `pyproject.toml` was clean — no imports to fix, just dep removal.

What I'm unsure about:
- The opencode `tool.test.ts` file doesn't test the tool invocation through the plugin lifecycle (because it would require a full opencode runtime). It tests `postReply()` directly, which is the logic, but the tool registration glue in `index.ts` is untested beyond TypeScript compilation. This is acceptable for v0.
- The `reply.ts` fire-and-forget `fetch` pattern works but silently swallows errors (`.catch(() => {})`). The test coverage for error paths is thin.
- The config test in the opencode adapter uses `require` cache busting which is a test smell. It works because `loadConfig` reads from disk on every call (no cache), but if caching is ever added these tests will break.

## Gaps to flag

- `adapters/claude/src/agent_wake_claude/_notify.py:8` — The `_stdout_lock` is a `threading.Lock()`. If a notification handler is ever called from the thread that already holds this lock (e.g., two wake events arriving while one is being written), it will deadlock. Low probability in v0 because all writes are short JSON lines, but it's a latent hazard.
- `adapters/claude/src/agent_wake_claude/server.py` — The `handle()` function does raw `sys.stdin.readline()` in a loop. No graceful shutdown mechanism. Ctrl-C will kill the process mid-read, which is fine for v0 but means in-flight wake events could be lost.
- `adapters/opencode/src/ingest.ts:8-18` — `recentEventIds` is module-level state with no locking. Bun's event loop is single-threaded so this is fine for now, but if the adapter ever uses Workers it will race.
- `adapters/opencode/src/ingest.ts:64` — `Bun.serve` is called inside the plugin function. If the plugin is loaded multiple times (e.g., hot reload), the second call will fail because the port is already bound. No cleanup mechanism.
- `core/examples/` — The example JSON files exist but there's no example config.json that a user could copy to get started. The README points to `core/schema.md` but doesn't provide a ready-to-use config.
- No `.gitignore` at the repo root. The `.venv/` in the Claude adapter and `node_modules/`/`dist/` in the opencode adapter are visible. The previous session had these in `.gitignore` at the adapter level, but there's no repo-level git to enforce it.
