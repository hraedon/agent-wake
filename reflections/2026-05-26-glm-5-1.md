# Session Reflection — 2026-05-26

**Work summary:** Implemented phases 1 and 2 of the v1 daemon spec. Phase 1 built the daemon skeleton (entrypoint, config, proto, socket_server, ingest stub, systemd unit). Phase 2 added full HTTP ingest with HMAC gating, dedupe, body wrapping, and source-bound routing to subscribed adapters over the unix socket. 75 tests passing, all acceptance criteria verified manually.

---

## On the project

The v1 daemon spec is well-structured — each phase has clear deliverables and acceptance criteria, which made implementation straightforward. The wire protocol design (newline-delimited JSON frames) is simple and correct for unix-domain sockets. The spec's decision to keep the external wire format unchanged from v0 while introducing a new internal protocol is smart; it means existing senders don't need to change.

One thing that struck me: the spec is 665 lines and densely cross-referenced. The phase boundaries are clean, but there are forward references (e.g., `reply_id` on the `reply` frame is defined in §4.3.7's commentary rather than §4.3.6's schema) that require reading the whole document carefully. This is fine for a canonical spec but would be rough if someone tried to implement a phase without reading the full doc first.

The existing claude adapter code is clean and well-tested, which made the port straightforward. The code style is consistent: type hints, `logging.getLogger`, no unnecessary abstractions.

## On the work done

Phase 1 was smooth — the only wrinkle was the `asyncio.StreamReader.readline()` buffer limit (default 64KB) which needed raising to 2×MAX_FRAME_SIZE, plus catching `ValueError` from the internal buffer overrun. This is a standard asyncio gotcha but worth noting since the spec doesn't mention it.

Phase 2 had one notable design choice: the Router now receives a `ClientConnection` object from the socket_server for `send_frame()`. The spec says "holds a writer reference per session" but the `subscribe()` method signature only lists `(session_id, adapter, instance, sources)`. I extended it to accept the connection object, which is the only practical way to deliver wake frames. This feels correct but deviates from the literal method signature in the spec.

The test infrastructure took some iteration. The aiohttp test client approach (using `TestClient`/`TestServer` from `aiohttp.test_utils`) works well but I initially tried the `aiohttp_client` pytest fixture (from `pytest-aiohttp`) which wasn't installed. Settling on direct `TestClient` avoided adding another dev dependency.

## On what remains

Phases 3–6 of the daemon spec:

1. **Phase 3 — outbox + reply**: `Outbox` class wrapping `aiohttp.ClientSession`, reply frame handling, `reply_result` delivery. Straightforward given the existing patterns.
2. **Phase 4 — claude adapter slim-down**: Delete `ingest.py`/`gating.py` from adapter, add `client.py` (unix-socket client), update `__main__.py`/`reply.py`/`config.py`. This is the most invasive phase since it touches the working adapter.
3. **Phase 5 — lifecycle/packaging**: SIGHUP config reload, systemd finalization, README updates.
4. **Phase 6 — e2e test + final docs**: `test_e2e.py`, README rewrite, schema.md update.

Order matters: 3 before 4 (adapter needs reply support), 4 before 5 (slimmed adapter needs to exist for docs), 5 before 6 (e2e test needs the full daemon).

## Gaps to flag

- **`accepted_sources` in `hello_ack` returns the adapter's full requested list when routing is empty (legacy mode)**. This matches the spec's `accepted_sources_for` computation but means an adapter that subscribes to `["foo", "bar"]` where only `foo` is configured gets `accepted_sources: ["foo"]` — the unconfigured source is silently dropped. This is correct per spec but worth double-checking the intent.
- **Router's legacy-mode scan is O(n) per deliver** — iterates `_order` in reverse. Fine at 16 connections but not indexed. Noted for future.
- **The `Dedupe` class has no lock** since it's single-threaded asyncio. If anyone calls it from a sync context (unlikely but possible during testing), it won't be thread-safe. The spec says "single event loop, no threading" so this is correct.
- **`daemon/.venv/` is in the working tree** — the `.gitignore` has `.venv/` but the daemon venv at `daemon/.venv/` might not be matched by that pattern depending on git's interpretation. Worth checking before committing.
- **The spec's §4.3.6 says `reply` has fields `source`, `in_reply_to`, `content` but §4.3.7 says `reply_id` should also be on the `reply` frame.** Proto validation enforces `reply_id` on reply frames. This is per the spec's inline correction but worth noting as a spec clarity issue.
- **No `body_too_large` check on the HTTP ingest side** (spec §13 mentions this as a deferred decision). The daemon will accept arbitrarily large HTTP bodies. Should be added in phase 2's ingest or explicitly documented as a known limitation.
