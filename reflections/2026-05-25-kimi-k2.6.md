## On the project

agent-wake is well-scaffolded for a v0 OSS project — two harness adapters (Claude Code MCP channels, opencode in-process plugin), shared config schema, HMAC-signature gating, and end-to-end tests. The code is small enough to hold in your head, and the event-schema contract (`core/schema.md`) is clear.

That said, the adapters are thin and there are a lot of "best-effort" disclaimers that hide real reliability holes: permission-relay forwarding silently drops failures with a `pass` comment, reply `POST`s are fire-and-forget with no retry, and in-memory dedup windows evaporate on restart. These are documented as v0 limitations, but the boundary between "limitation we chose" and "bug we should fix before v1" is blurry.

The test coverage is decent for unit-level logic (signature verification, config loading, dedup, ingest routing) but there are no tests for:
- The source-spoofing check I added (both adapters).
- The XML-escaping path in `formatWakeEvent`.
- The MCP server's catch-all `except` sending `-32603` on unhandled exceptions.

I didn't add them because the existing tests already needed to pass first and the user asked for an adversarial review + fix cycle, not an expansion of the test matrix.

## On the work done

I read every source file in the repo (non-dependency, non-generated) before touching anything. That let me spot cross-cutting issues like the source-spoofing vector in both adapters and the XML-injection vector in opencode. The fixes are minimal:

1. **Source spoofing (high)** — `ingest.py` and `ingest.ts` now enforce that the authenticated `X-AgentWake-Source` header matches the body's `source` field on passthrough v0 events. Raises 500 on mismatch (fail-shut).
2. **XML injection (high)** — `formatWakeEvent` escapes `& < > " '` before interpolating into the `<wake>` tag. Prevents attackers from breaking out of the tag or injecting phantom attributes.
3. **MCP catch-all exception (high)** — `server.py` now sends `-32603` for any unhandled exception when the request had an `id`, so Claude Code doesn't wait forever on a dead request.
4. **fakechat-test portability (medium)** — Replaced the hardcoded `python3.12` venv path with a `sys.version_info`-based lookup.
5. **Test isolation (medium)** — `test_server.py` now restores monkey-patches in `finally` blocks so later tests don't see stale state.
6. **Docs / CI papercuts (low)** — Fixed `source`→`sources` README typo, demo script path, `.env` in `.gitignore`, `npm run build` → `bun run build` in CI.

Confidence: high on the security fixes (they're mechanical), medium on the XML escaping (I used standard HTML/XML entity set; if opencode ever changes its parsing this could matter, but it's safe for now).

## On what remains

1. **Tests for the new security checks** — The source-spoofing and XML-escaping paths have no unit test coverage. Add them before v1.
2. **Reply retry / outbox** — `reply.py` and `reply.ts` fire POSTs without retry and the fetch promise in `postReply` is barely awaited. If the callback is down, the reply is lost silently. A bounded retry + dead-letter log would make this production-usable.
3. **Permission relay logging** — I added a `TODO` comment but no actual logging mechanism. `_forward_permission_request` still swallows every exception type.
4. **Durable dedup** — In-memory 256-event window means restarts are vulnerable to replay. Needs a substrate-backed or file-backed window for v1.
5. **Multi-session routing** — opencode broadcasts to all active sessions; Claude Code has session-scoped channels only. Per-session routing is deferred but should be designed before v1.
6. **Unrelated files in working tree** — `adapters/opencode/package-lock.json` changed for the second time in two sessions, which suggests it keeps getting rebuilt (by me or a previous agent). It should either be committed cleanly once or added to `.gitignore` if it's truly build output.

## Gaps to flag

- `adapters/claude/src/agent_wake_claude/ingest.py:50` — The 500 response body on source mismatch leaks more info than a plain 403; it includes both the header and body source strings. Acceptable for debugging but could reveal internal source names to an attacker who can forge a v0 event body.
- `adapters/opencode/src/ingest.ts:120` — When `activeSessions.size === 0`, the event is accepted (202) but dropped on the floor. There's no durable queue. This is documented in the schema but still a real data-loss hole.
- `adapters/opencode/src/reply.ts:23` — `fetch` promise rejected errors are logged to `console.error` but the calling tool only sees `"sent"`. This is misleading if the callback never received the payload.
- `core/schema.md:119` — `403 Forbidden` says "No leakage of whether the source is configured." But `ingest.py` checks `source_cfg` first and returns the exact same 403 string for both "unknown source" and "bad signature". Good. But `ingest.ts` does the same. Keep this invariant if the error message ever diverges.
- No `.env.example` or `README` guidance on secret rotation / key management. For a project that handles HMAC secrets, this should be explicit.
- `ci.yml:27` — The verify-installability step uses `pip install ./adapters/claude`, which changes PYTHONPATH behavior. If hatchling needs the repo root it could fail; watch the first CI run.
